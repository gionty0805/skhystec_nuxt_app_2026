# 🚀 Nuxt 4 내·외부 API 모듈화 웹 서비스

소규모 팀의 빠른 개발 생산성과 강력한 보안을 위해 **BFF(Backend For Frontend) 아키텍처**로 설계된 풀스택 웹 애플리케이션 프레임워크입니다. 외부는 인증 API로, 내부는 대시보드 및 세션 관리 전용으로 폴더를 명확히 분리하여 관리합니다.

---

## 📌 권장 개발 환경 (Prerequisites)

프로젝트 구동을 위해 아래 버전을 반드시 준수해 주세요. 버전이 맞지 않으면 빌드 시 오류가 발생할 수 있습니다.

| 항목 | 권장 사양 | 확인 명령어 |
| :--- | :--- | :--- |
| **Node.js** | **v20.x 이상** (LTS 권장) | `node -v` |
| **NPM** | **v10.x 이상** | `npm -v` |

---

## 🛠️ 개발 시작하기 (Quick Start)

### 1. 저장소 클론 및 패키지 설치
GitHub에서 코드를 내려받은 후, 라이브러리를 설치합니다. (`node_modules`는 Git에서 제외되어 있으므로 최초 설치가 필수입니다.)
```bash
npm install
```

### 2. 환경 변수 세팅 (`.env`)
프로젝트 루트(최상위) 위치에 `.env` 파일을 생성하고 외부 백엔드 주소를 입력합니다.
```env
# .env
EXTERNAL_BACKEND_URL=https://your-backend.com
```

### 3. 로컬 개발 서버 실행
```bash
npm run dev
```
> 서버가 가동되면 브라우저에서 `http://localhost:3000`으로 접속합니다.

## 🚨 자주 발생하는 오류 및 해결 가이드 (Troubleshooting)

### 1. `npx` 설치 실패 또는 GitHub 다운로드 실패 (`fetch failed`)
`npx nuxi@latest init` 도중 네트워크 프록시나 방화벽 문제로 템플릿 다운로드가 막히는 경우입니다.
* **해결책**: `degit` 도구를 이용하여 GitHub 캐시를 우회해 강제로 다운로드합니다.
  ```bash
  npx degit nuxt/starter#v4 nuxt-app
  ```

### 2. `[NUXT_E4014] No pages found` 에러 발생
Nuxt 4 컴파일러가 페이지 컴포넌트를 인지하지 못할 때 발생합니다.
* **해결책**: Nuxt 4 폴더 규격에 맞게 `pages` 폴더가 최상위가 아닌 **`app/` 폴더 내부**에 위치해야 합니다.
  ```text
  └── app/
      ├── app.vue
      └── pages/
          ├── index.vue
          └── login.vue
  ```

### 3. 로그아웃 시 `404 Page not found` 에러 발생
새로운 API 파일을 생성했으나 Nuxt 내부 라우터 엔진이 실시간 캐시를 갱신하지 못해 주소를 찾지 못하는 현상입니다.
* **해결책**: 파일명이 `logout.post.ts`로 정확한지 확인 후, 가동 중인 터미널을 완전히 종료(`Ctrl + C`)하고 **서버를 다시 시작**해 주세요.
  ```bash
  npm run dev
  ```

## 📂 프로젝트 폴더 구조 명세 (Folder Structure)

```text
├── app/
│   ├── pages/
│   │   ├── index.vue           # 메인 대시보드 화면 (내부 API 호출)
│   │   └── login.vue           # 서비스 로그인 화면 (외부 API 호출)
│   └── app.vue                 # <NuxtPage /> 라우팅 엔트리
├── server/
│   ├── api/
│   │   ├── innerapi/           # [내부 전용] 대시보드 데이터 및 로그아웃(세션 파기)
│   │   └── outerapi/           # [외부 연동] 외부 백엔드 API 중계 및 CORS 우회
│   └── plugins/
│       └── logger.ts           # [글로벌 로깅] 모든 API 요청/응답/크래시 에러 모니터링
├── .env                        # 보안 및 환경변수 설정 파일 (Git 업로드 금지)
├── .gitignore                  # 무거운 파일 및 보안 파일 업로드 차단 설정
└── nuxt.config.ts              # 보안 HTTP 헤더 및 Nuxt 4 시스템 설정 파일
```

## 🛡️ 시스템 보안 및 모니터링 적용 사항

* **SQL/NoSQL Injection 방지**: `outerapi` 내부에서 정규식(`/['";-]/g`) 및 타입 캐스팅을 통해 악성 특수문자 선제 차단.
* **XSS 방지**: Vue.js 자동 이스케이프 렌더링 도입 및 `httpOnly: true` 쿠키 설정으로 브라우저 단 자바스크립트 토큰 탈취 원천 봉쇄.
* **CSRF 방지**: 인증 쿠키 속성에 `sameSite: 'strict'`를 명시하여 제3자 사이트의 요청 위조 방어.
* **보안 헤더**: `X-Frame-Options`, `X-Content-Type-Options`를 일괄 적용하여 웹 취약점 방어.
* **서버 로깅**: 모든 API 호출의 처리 시간(`ms`)과 500 서버 크래시 에러 발생 시의 `Stack Trace`를 터미널에 실시간 기록.

## 🚀 운영 서버 배포 (Production Deployment)

### 1. 배포 컴파일 빌드
```bash
npm run build
```
> 빌드가 완료되면 독립 실행이 가능한 최적화 묶음인 `.output/` 폴더가 생성됩니다.

### 2. PM2를 통한 무중단 배경 가동 (권장)
운영 Linux 서버에 `.output/` 폴더를 복사한 후 터미널이 닫혀도 안정적으로 운영되도록 프로세스를 백그라운드에 등록합니다.
```bash
# PM2로 서비스 가동
pm2 start .output/server/index.mjs --name "nuxt-production-app"

# 실시간 모니터링 로그 확인
pm2 logs nuxt-production-app
```


# 🗺️ Nuxt 3 보안 로그인 및 자동 리다이렉트 아키텍처

본 문서는 브라우저 자바스크립트가 접근할 수 없는 보안 `httpOnly` 쿠키와 Nuxt 3 라우터 미들웨어를 활용하여 구축한 프로젝트 전역의 **보안 로그인 및 자동 리다이렉트 메커니즘**을 설명합니다.

---

## 💻 1. 단계별 전체 흐름도 (Step-by-Step Flow)

* **[1단계] 보호된 페이지 접속 시도**
  * 사용자가 인증이 필요한 경로(예: `/equipment/entry`)로 진입합니다.

* **[2단계] 출입 통제관 작동 (`middleware/auth.global.ts`)**
  * 화면이 브라우저에 그려지기 전(SSR 단계)에 미들웨어가 먼저 요청을 가로챕니다.
  *단, 무한 루프를 방지하기 위해 `/login` 경로 접근은 검사 대상에서 제외하고 그대로 통과시킵니다.

* **[3단계] 세션 검증소 상태 조회 (`server/api/outerapi/check-session.get.ts`)**
  * 브라우저의 `cookie` 헤더를 Nuxt 서버 내부로 안전하게 토스하여 현재 보유한 `httpOnly` 쿠키의 존재 유무를 확인합니다.
  * **[케이스 A] 인증 쿠키가 존재하는 경우**
    * 정상 로그인 유저로 판단하여 화면 가상 DOM 하이드레이션 단계를 완료합니다.
    * 클라이언트 전역 플러그인이 가동되어 제이쿼리 달력(DatePicker) 등 UI 컴포넌트를 바인딩하고 페이지를 정상 오픈합니다.
  * **[케이스 B] 인증 쿠키가 없는 경우**
    * 비로그인 유저로 판단하여 즉시 출입을 통제하고 [4단계]로 분기합니다.

* **[4단계] 로그인 화면으로 강제 이동 및 목적지 박제**
  * 미인증 사용자를 로그인 화면으로 리다이렉트 시킵니다. (`/login?redirect=/equipment/entry`)
  * 이때 사용자가 원래 보려고 했던 주소를 주소창 쿼리 스트링에 안전하게 기억해 둡니다.

* **[5단계] 로그인 시도 및 데이터 정제**
  * 사용자가 로그인 폼에 아이디와 패스워드를 입력하여 제출합니다.

* **[6단계] 로그인 처리기 검증 (`server/api/outerapi/login.post.ts`)**
  * SQL 인젝션 공격 방지를 위해 아이디 내 특수문자(`'";-`)를 검증 및 차단합니다.
  * 내부 보안 우회 정책에 따라 지정된 마스터 테스트 계정(`9111713`)은 외부 API 통신 없이 예외 승인 처리합니다.
  * 일반 계정은 런타임 설정에 등록된 외부 백엔드 인증 API 서버와 안전하게 동기화 통신을 진행합니다.

* **[7단계] 보안 쿠키 발행 (`setCookie`)**
  * 외부 백엔드 또는 내부 인증 로직에서 발급한 토큰을 브라우저에 세팅합니다.
  * 악성 스크립트 탈취 공격(XSS)을 원천 차단하기 위해 `httpOnly: true`, `sameSite: 'strict'` 속성이 적용된 안전한 비밀 상자 형태로 발급합니다.
  * 쿠키 세팅이 완벽히 끝나면 프론트엔드로 `{ success: true }` 응답을 반환합니다.

* **[8단계] 원래 목적지로 자동 복귀 (`pages/login.vue`)**
  * 로그인 처리가 최종 성공하면 컴포넌트 로직이 활성화됩니다.
  * 주소창에 저장해 두었던 `route.query.redirect` 경로를 읽어내어 사용자가 로그인 전에 작업하려던 화면으로 부드럽게 자동 워프시킵니다.

## 🔒 2. 3대 핵심 보안 설계 및 이점

### 🛡️ 전역 미들웨어 통제 (화면 깜빡임 현상 제로)
* **기존 SPA 방식**: 화면이 브라우저에 다 그려진 뒤 자바스크립트로 세션을 체크해 뒤늦게 주소를 바꾸기 때문에 비로그인 유저에게 내부 데이터가 순간 노출되는 결함이 존재합니다.
* **개선 방식**: Nuxt 3 서버 사이드(SSR) 가동 단계에서 전역 미들웨어가 먼저 개입하므로 비로그인 유저의 화면 접근을 웹서버 상에서 원천 봉쇄합니다.

### 🔑 `httpOnly` 비밀 상자 (XSS 토큰 탈취 공격 완전 방어)
* **보안 핵심**: 발급하는 인증 토큰은 브라우저 자바스크립트(`document.cookie`)가 절대로 열어보거나 해킹할 수 없는 `httpOnly: true` 속성으로 격리됩니다.
* **연동 원리**: 브라우저가 보안 검증소(`check-session`)에 신호를 보낼 때 자동으로 쿠키 상자가 유기적으로 전달되므로, 보안을 최고 수준으로 유지하면서도 자연스러운 상태 조회가 가능합니다.

### 🧭 유연한 주소창 복귀 시스템 (`?redirect=...`)
* **UX 강화**: 미인증 유저 이탈 방지를 위해 리다이렉트 발생 시 기존 목적지를 주소창에 쿼리 파라미터로 안전하게 물려 전송합니다. 사용자가 로그인을 완료하는 즉시 원래 작업 중이던 흐름으로 자연스럽게 돌려보냅니다.
